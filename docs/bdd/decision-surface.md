> 狀態：**已實作，待 QA**（2026-10-08）。AC-DS-01 的起點目前是由膠囊位置推得的瀏海形狀，邊緣瀏海交付後改為真正的瀏海。

> 確認題作答、按鈕文字、焦點與鍵盤、回執 Markdown、長網址；新增場景 14（窄螢幕）、15（確認題）。
> QA 第 2 輪修正（2026-10-09，Ray 核准）：單欄斷點改以面板本身寬度判斷、與題組共用（場景 14）；往外開等讓開完成才打開，
> AI 回饋／證據行／時間軸的連結也能打開（場景 13）；題組送出後焦點與回執 Markdown（場景 7、9）；切題真的淡入（場景 10）；
> 新增場景 16（被其他通道結案的題就地唯讀）。
> QA 第 3 輪修正（2026-10-09，Ray 核准）：蓋板裡答完最後一題的回執不再一閃即逝（收起判斷不早於這次作答的結果、收起緩衝期間
> 面板照樣掛著，場景 9）；主視窗的作答流程也跟著最新清單（場景 16）；選項標題、選項說明與回執「你選的選項」裡的連結打得開，
> 點連結不會選取或取消選項（場景 13）；歷史紀錄回看已結案的題一律唯讀、狀態依實際終態（場景 10、新增場景 17）；「稍後再問
> 沒有成功」的錯誤不再蓋住題目、進度點的無障礙名稱依實際終態（場景 16）。

> 右上改成「關閉」（場景 17）；新增場景 18（面板自帶深色：color-scheme、主視窗裡的黑底、全形標點交給蘋方）。

## 背景

舊版問題：(1) 送出鍵藏在輸入框裡，最底下右邊（一般認知的確認位置）是「這題不該問我」；(2) AI 給一長串
文字與數字，沒有圖表、看不到脈絡；(3) 墨水圓形轉場和提醒物件沒有空間關係；(4) 左半邊被裝飾性粒子
圖像佔據。

## 行為規格

### 場景 1：瀏海張開成面板

**Given** 邊緣瀏海可見，使用者點擊它（或題目到期強制顯示）
**When** 面板開始出現
**Then** 黑色形狀先沿瀏海所在邊延伸到面板全長（約 300 ms），再往螢幕內展開成面板（約 480 ms，臨界阻尼、
不回彈）；面板以外的螢幕全程完全透明，沒有任何變暗或模糊的半透明層（2026-10-09 Ray：只讓人看到黑色面板展開）；
來源圖示從瀏海頭端飛到面板左上角；內容在形狀展開後以每項 45 ms 的間隔依序淡入（只在張開時，切題不重播）；收起時從
當下的形狀倒放回瀏海；全部題目結案時瀏海縮回邊框消失。
形狀定案前（約 0.93 秒）面板整個不可操作（`inert`：點不到、Tab 不進去），只有 Esc 有效——Esc 從面板掛載的那一刻
起就等同「稍後再問」，不必等動畫跑完。動畫迴圈沒有執行（例如視窗還在背景）時，計時後備最晚 1.2 秒讓面板定案、
收起最晚 0.9 秒完成，不會卡在半開。
系統「減少動態效果」或 Kunsu 設定的「連續轉場動畫」關閉時，不播形狀與圖示飛行，改為 160 ms 淡入、收起時 160 ms
淡出（全域的減少動態規則不得把這 160 ms 壓成瞬間），功能不變；此時面板貼齊瀏海所在的邊，只有朝螢幕內的兩個角是圓角

### 場景 2：證據｜決定 兩欄

**Given** 題目帶有證據內容（Markdown 或畫布）
**When** 面板顯示
**Then** 左欄依序是「為什麼問你」卡片與證據（可獨立捲動），右欄只放這一題的決定：「要你決定」標籤、
一句話題目、不決的後果與期限、（錢題）所見即所簽參數、選項、補充說明、底部操作列；右欄底部操作列永遠
可見，不隨左欄捲動

### 場景 3：沒有證據時改成單欄

**Given** 題目沒有任何證據（只有脈絡與題目）
**When** 面板顯示
**Then** 版面改成置中單欄（最寬 760 px）：為什麼問你 → 題目 → 選項或回答框 → 操作列；不出現空的左欄

### 場景 4：按鈕位置不再誤導

**Given** 任一題目
**When** 使用者看操作區
**Then** 右下角只有一個主要動作，未選選項也未輸入文字時為停用狀態；「稍後再問 Esc」在右上角，按鈕上直接寫出
後果「N 分鐘後再問」（看得到的文字，不是滑鼠提示）；N 是目前生效的強制週期長度：面板打開時讀設定（`settings_get` 的
`effective.force.cycle_min`），使用者在設定頁改成 30 分鐘就寫「30 分鐘後再問」；讀不到或還沒讀到時寫「15 分鐘後再問」（2026-10-09，
取代寫死的 15）；「這題不該問我」在左下角，為次要文字按鈕；三者位置固定，
不因題型改變。主要動作的文字依題型（與 CONTRACT §9 同一張表）：

| 題型／狀態 | 右下主按鈕 |
|---|---|
| 選擇題（一般） | 送出決定 |
| 文字題，或沒有可選的選項（含十秒可決沒過被鎖選項） | 送出回答 |
| 確認題（`kind = confirm`、沒有選項） | 確認 |
| 黃燈錢題選了 AI 建議（執行型）選項 | 批准並執行 |
| 錢題選了選項但一鍵被鎖（紅燈、升紅、缺 prediction） | 拍板此選項（不執行） |
| 送出中 | 送出中… |

### 場景 5：選項是單選，不會誤送

**Given** 選擇題有 2–4 個選項
**When** 使用者點選項或按 1–4
**Then** 只會選取（再點一次取消），不會直接送出；選取狀態以白色外框與編號底色表示並同步 `aria-checked`；
AI 建議的選項標「AI 建議」；選項下方顯示「你的決定：…」摘要；Enter 或點主要動作才送出。焦點停在某個選項上按
Enter 時送出的是目前明確選取的那一個（沒有選取就什麼都不送），絕不會因為 Enter 把選取改成焦點所在的選項；錢題相同

### 場景 6：選項加補充說明

**Given** 使用者選了選項，又在補充說明輸入文字
**When** 送出
**Then** 答案同時保存 `choice_id` 與補充文字（`free_text`），回執兩者都顯示；只輸入文字未選選項時以自由
回答送出；錢題的補充說明不會改變所見即所簽參數（改金額仍走既有 edit_option 紅線流程）

### 場景 7：鍵盤

**Given** 面板開啟
**When** 使用者只用鍵盤
**Then** 1–4 選選項；Tab 進補充說明；在補充說明中 Enter 送出、Shift+Enter 換行、輸入法組字中的 Enter 不送出；
焦點在選項上 Enter 送出目前選取（場景 5）；焦點在其他按鈕或連結（這題不該問我、打開原對話、上一題／下一題、稍後再問、
改金額、內文連結）上 Enter 只啟動那個控制項，不會送出或跳題；Esc 稍後再問（行內編輯中的 Esc 只收起編輯，輸入法組字中的
Esc 只取消組字）；送出後焦點移到回執的「下一題／完成」（題組也一樣，焦點不會掉到頁面本體），Enter 前往下一題；回執裡
焦點在連結或其他按鈕（打開原對話、AI 回饋裡的連結、題組回執的項目列）上按 Enter 只啟動那個控制項，不會跳題；焦點順序：
選項 → 補充說明 → 這題不該問我 → 送出；開啟時焦點落在第一個選項（文字題落在回答框）；面板是對話框，Tab／Shift+Tab 在
面板內循環，不會跑到面板後面

### 場景 8：為什麼問你

**Given** 題目有 `why_md`（或舊題只有 `body_md`）
**When** 面板顯示
**Then** 卡片顯示脈絡摘要；以時間（`09:30`、`現在`）開頭的清單自動呈現為時間軸，最後一項高亮；有原對話
身分時提供「打開原對話」；提供「看 AI 送來的原文」顯示本題實際內容與字數；舊題沒有 `why_md` 時以
`title` 加 `body_md` 首段代替

### 場景 9：回執就地顯示

**Given** 使用者送出答案
**When** 答案寫入成功
**Then** 右欄就地換成回執：你的決定與補充、「✓ 已收到（時間）」「✓ 已寫入決策帳本」與 conversation-continuity
定義的交付狀態，可打開原對話；題目與選項文字和作答時一樣經 Markdown 渲染（不出現 `**` 等原始符號），執行失敗畫面
與題組回執相同；有下一題時提供「下一題 ⏎」，沒有時「完成 ⏎」並收回瀏海；失敗時顯示可重試錯誤且保留草稿，不得誤顯成功。
在強制蓋板裡答完最後一題（佇列已沒有未結案題）時，蓋板不會自己消失：回執（交付狀態、AI 回饋輪詢）留在畫面上，
直到使用者按「完成 ⏎」或 Esc 才收起（2026-10-09，取代 overlay-presentation 舊 AC-OP-07 的「全部結案就自動隱藏」）。
server 作答時會先通知清單變更（最後一題已結案、佇列變空）再回傳作答結果，所以蓋板的收起判斷**不能早於這次作答的結果**：
從按下送出到結果回來，蓋板一律不收起；「佇列空了要收起」有 300 ms 緩衝，緩衝期間面板照樣掛著，面板一回報正在顯示這次送出
的回執就取消收起（2026-10-09 QA 第 3 輪：舊版先看到「0 題」就立刻卸載面板，回執在 50 ms 內消失）

### 場景 10：多題切換

**Given** 佇列有多題
**When** 使用者按上一題／下一題或點進度點
**Then** 只淡出淡入面板內容：舊內容 140 ms 淡出，新內容掛上時 140 ms 從透明淡入（不是一出現就不透明）；減少動態時
直接換、不做淡出淡入；不重播張開動畫、不重設任何倒數；頁首顯示「第 N 題，共 M 題」與進度點（已答為灰點）；已回答的
題目回看時顯示回執，不可修改。進度點的無障礙名稱依實際狀態：「第 N 題」「第 N 題（已回答）」「第 N 題（已退回重擬）」；
被其他通道結案的寫「第 N 題（已結案：已由 Discord 回答）」等實際原因，不一律寫「已回答」

### 場景 11：面板不顯示倒數

**Given** 題目仍在週期內或已逾時
**When** 面板顯示
**Then** 頁首不顯示倒數圓環、「m:ss 後強制詢問」或「已到期」，也不做倒數公告；15 分鐘週期只在背景計算
（2026-10-09 Ray）。頁首右側只有「稍後再問」；倒數提醒只出現在面板打開前的瀏海

### 場景 12：來源身分在頁首

**Given** 任一題
**When** 面板顯示
**Then** 頁首左側顯示來源 AI 官方圖示與名稱、任務名稱與觸發方式（排程／互動）、提出時間；不再有左側大型粒子
圖像

### 場景 13：往外開時蓋板先讓開

**Given** 強制蓋板顯示中（蓋板在所有視窗之上）
**When** 使用者點「打開原對話」、「轉討論給 Claude」、Kongko 連結，或任何 Markdown 連結的第二次點擊（內文、為什麼問你、
時間軸、證據行、題組原文、一般題與題組回執裡的 AI 回饋）
**Then** 蓋板先讓開再打開目標，目標 App 或瀏覽器不會開在蓋板後面看不到：題目還沒回答就跟「稍後再問」相同（記一次
關閉、重新開始 15 分鐘週期，不算處理）；已回答（回執）就直接關閉。「讓開」要整個完成——dismissal 成功、收起動畫跑完、
蓋板視窗隱藏——之後才送出打開目標的請求；讓開失敗（dismissal 被拒）時不打開目標，面板顯示錯誤。每一個 Markdown 連結
都接上同一個打開入口，第二次點擊一定有反應。主視窗裡的作答流程是一般視窗，直接打開、不讓開
**And** 選項標題、選項說明與回執的「你選的選項」裡的連結也接同一個入口（2026-10-09 QA 第 3 輪）：連結不包在選項按鈕裡
（選項卡片的可點擊區是一顆鋪滿卡片的 radio 按鈕，標題與說明疊在上面、只有連結本身接收點擊），點連結只走連結的
「再按一次用瀏覽器開啟」流程，不會選取或取消那個選項；連結可以用 Tab 走到、Enter 開啟（同樣第二次才開）；radio 的
無障礙名稱仍是選項標題（含「AI 建議」）、說明是它的描述

### 場景 14：窄螢幕不重疊

**Given** 有證據的題目（或題組），**面板本身**寬度小於 1100 px（例如主視窗預設 980×720；蓋板在 1100 px 寬的螢幕上面板
只有約 1086 px，也算）
**When** 面板顯示
**Then** 以面板寬度判斷（CSS container query，不看視窗寬度），一般題與題組用同一個斷點、同一條規則（< 1100 px 單欄，
≥ 1100 px 兩欄），不會有某個寬度一邊單欄、一邊兩欄而捲不動；兩欄改成單欄：證據在上、決定在下，證據撐開自己的高度，整個內容區一起捲動（不再各自捲動）；任何內容都不會
互相重疊；底部操作列固定在面板底部、永遠看得到，內容區底部留出操作列的高度，最後一行可以捲到操作列上方；任何寬度
下捲動的內容都不會從操作列下方露出；長網址或沒有斷點的長字串會換行，決定欄不出現橫向捲動

### 場景 15：確認題可以直接確認

**Given** 一題 `kind = confirm` 且沒有選項的確認題
**When** 使用者按「確認」（可附補充說明）
**Then** 答案以 `choice_id = "confirm"` 送出並被 server 接受（與 `free_text` 補充一起保存），回執顯示「確認」；交給發問
AI 的訊息寫明使用者的選擇是「確認」；確認題不會觸發錢鏈（錢鏈只認黃燈錢題的執行型選項）

### 場景 16：被其他通道結案的題就地唯讀

**Given** 面板開著，session 裡有一題還沒在面板裡作答
**When** 那一題被其他通道結案（Discord 或 CLI 回答、出題的 AI 取消或取代、過期）
**Then** 那一題就地換成唯讀畫面：標籤「已在其他地方結案」、一行說明發生什麼事（例如「已由 Discord 回答」「出題的 AI 已
取消」「已過期」）、沒有選項、輸入框與送出鈕，只有「下一題／完成」；進度點標成已結案；使用者正在送出的那一題不受影響
（以送出結果為準）
**And** 主視窗裡的作答流程（「開始處理 N 題」、待決清單點一題、蓋板就緒逾時改開主視窗）也跟著最新清單，行為與蓋板相同：
被其他通道結案的題就地唯讀、session 開著時才到期的強制題接到尾端、題組重新註冊時保留使用者的修改並標「AI 更新了這一項」、
送出帶新版本雜湊（2026-10-09 QA 第 3 輪：舊版主視窗只拿開啟當下的清單，之後怎麼變都看不到）。從歷史紀錄回看已結案的題
只跟著那幾題的最新資料（例如 AI 回饋），不把強制題接進來（回看不是作答 session）
**And** 「稍後再問沒有成功」的錯誤（`role="alert"`）顯示在頁首下方、內容上方的流內區塊，把內容往下推，不蓋住「要你決定」
與題目

### 場景 17：回看已結案的題

**Given** 主視窗「歷史紀錄」點一題已結案的題（一打開就已經是終態，不是在這次 session 裡結案）
**When** 面板顯示
**Then** 一律唯讀，沒有選項、回答框與送出鈕；狀態文字依實際終態：已回答 → 回執（你的決定、交付狀態、AI 回饋）；過期 →
「已過期」＋「沒有回答」（逾時依預設選定時寫「沒有回答（逾時依預設：選項）」）；出題的 AI 取消 →「AI 取消了這題」；使用者
用「這題不該問我」推掉（有 `rejected`）→「已退回重擬」＋「你退回了這題：原因」；被新版本取代 →「被新題取代」。「已退回
重擬」只用在使用者自己推掉的題，AI 取消的題不會被寫成使用者退回（2026-10-09 QA 第 3 輪）；題組相同
**And** 回看時頁首右上沒有「稍後再問」（已結案的題沒有東西可以再問），改成「關閉 Esc」；按它或 Esc 收起面板，回到歷史紀錄
原本的篩選與捲動位置（application-shell 場景 5；2026-10-09 主視窗 QA 第 1 輪）

### 場景 18：面板自帶深色

**Given** 主視窗是淺色主題（`<html>` 宣告 `color-scheme: light`）
**When** 使用者從主視窗打開決策面板（開始處理、點待決列、回看歷史）
**Then** 面板舞台自己宣告 `color-scheme: dark`：補充說明的縮放把手、拼字底線、自動填入與沒自訂的捲軸都是深色樣式，和蓋板裡
一模一樣；主視窗裡面板背後的舞台是黑底，面板周圍不露出淺色的主視窗邊（蓋板裡舞台仍全透明，場景 1）
**And** 面板文字的字型限定和主視窗相同：Geist 只排英文字母、數字與半形標點，中文與全形標點（，。；：「」）交給蘋方，所以
「第 1 題，共 8 題」的逗號是全形，不會被排成半形的「,」
