# 強制蓋板呈現可靠性（overlay-presentation）— BDD 驗收規格

> 狀態：**Target（2026-10-08 規劃，待 Ray 確認）**；修復現行 P0 bug，完成前不得勾選。
> 產品依據：`docs/PRD.md` §22；視覺依據：`DESIGN.md`「Overlay presentation reliability」「Agent marks」。
> 擬新增不變量：`inv_overlay_never_blank`、`inv_overlay_covers_target_display`（與紅燈測試同 commit 寫入 INVARIANTS.md）。
> 界外：倒數／dismissal 語意（見 forced-question-cycle.md）、邊緣瀏海（見 edge-notch.md）。

## 背景與根因（2026-10-08 調查）

1. **蓋板跑版（間歇）**：shell 先 `set_position` 再 `set_size`。macOS `setContentSize` 以左下角為錨
   向上長高，視窗以初始 1280×800 的高度先對齊螢幕頂端，再向上長 317 pt：上緣超出螢幕、下方
   28.4% 沒覆蓋，與使用者截圖（下緣約 y≈926/1293）完全吻合。每次 app 啟動後第一次開蓋板必錯。
   另有潛在問題：位置與大小用目標螢幕倍率換算，但視窗端以「目前所在螢幕」倍率還原，混用
   2x 內建螢幕與 1x 外接螢幕時會放大或縮小一倍。
2. **啟動即卡死（必現）**：launch reconcile 在蓋板網頁註冊監聽前就送出 `kunsu://overlay_transition`。
   Tauri 事件不暫存，事件遺失 → 內容永不掛載，只剩原生模糊背景；Esc 只掛在題目卡上所以無效；
   之後「session 已開且視窗可見」的早退判斷讓事件永不重送，只能用勿擾快捷鍵逃生。
3. **同路徑的潛在問題**：轉場事件廣播給所有視窗；蓋板網頁每次啟動都跑 700 ms 自動關閉計時，可能
   誤關正在載入的強制題；勿擾狀態讀取失敗時預設 active，導致所有主動 surface 每秒被隱藏。

## 行為規格

### 場景 1：蓋板精準覆蓋目標螢幕

**Given** 任一螢幕配置（內建 2x、外接 1x、外接螢幕在內建螢幕上方或左方），且蓋板視窗先前的大小
與位置任意（包含建立時的 1280×800）
**When** 系統要顯示蓋板
**Then** 在視窗被帶到前景之前，以目標螢幕完整 frame（邏輯點、含選單列區域）一次設定視窗 frame；
顯示後讀回實際 frame，與目標誤差 > 0.5 pt 時立即重套並寫診斷事件；使用者看不到任何「先錯再對」
的過渡畫面

### 場景 2：目標螢幕的選擇

**Given** 有一題要強制詢問
**When** 決定蓋板要出現在哪個螢幕
**Then** 依序選：邊緣瀏海（或現行膠囊）所在螢幕 → 游標所在螢幕 → 主螢幕；轉場起點座標以同一螢幕
換算，墨水擴散起點與瀏海圖示中心誤差 ≤ 2 pt。沒有點擊座標時（題目自動到期、從選單列開啟、批次窗），起點用瀏海網頁
最後一次回報的圖示中心（瀏海每次位置或長度改變後回報，原生層記住最新一筆）；瀏海還沒回報過才退回固定估計值。瀏海在
右邊或下邊時，面板從右邊或下邊張開，不會從左上角
（2026-10-09 QA 第 2 輪）

### 場景 3：螢幕設定改變時重新對齊

**Given** 蓋板可見
**When** 外接螢幕插拔、解析度或排列改變、Mac 睡眠喚醒後螢幕重排
**Then** 下一個 runloop 內重新計算目標螢幕並重套 frame；目標螢幕消失時移到主螢幕；不會留下半張蓋板

### 場景 4：內容就緒握手，絕不出現空白蓋板

**Given** 蓋板網頁可能仍在載入（例如 app 剛啟動、renderer 重新載入）
**When** 有一題需要強制詢問或使用者點擊瀏海
**Then** shell 不得把蓋板視窗帶到前景，直到該視窗網頁回報「已掛載可操作內容」：題目文字、回答輸入與
關閉控制都已渲染；轉場事件只送給蓋板視窗（不廣播），且網頁掛載時會主動拉取「目前待播的轉場」，
所以事件不會因時序遺失；每個轉場有 id，重複送達只播一次

### 場景 5：就緒逾時改走主視窗後備

**Given** shell 已請求顯示蓋板
**When** 1.5 秒內沒有收到該轉場 id 的「已掛載」確認
**Then** 蓋板保持隱藏（已顯示則立即隱藏）；開啟主視窗並聚焦該題，題目維持強制資格：不算回答、不算
dismissal、不重設週期；同時重新載入蓋板網頁，下一次狀態檢查再嘗試；每次逾時寫診斷事件，連續三次
逾時發 Discord 告警

### 場景 6：Esc 與關閉永遠有效

**Given** 蓋板可見，無論內容是否已掛載、網頁是否無回應、目前在選項或輸入模式
**When** 使用者按 Esc 或關閉按鈕
**Then** 走同一條關閉路徑：未回答題記 dismissal 並開始新週期，蓋板隱藏、回到瀏海；網頁 2 秒內沒處理
Esc 時，由原生層接手完成相同關閉；dismissal 呼叫失敗時面板**不收起**，以 `role="alert"` 顯示可讀錯誤（例如「稍後再問
沒有成功：…。再按一次 Esc 或「稍後再問」重試」），可以再試，不會「按了沒反應」。網頁只有在真的處理了這個 Esc 時才通知
原生「已接手」：稍後再問／關閉要等 dismissal **成功**才通知（失敗就不通知，原生 2 秒後備照樣完成同一 dismissal 並隱藏，
不會卡住）；收起行內輸入框（焦點真的在 textarea／input／contenteditable 裡）或取消輸入法組字當下就通知；面板還沒掛載
或正在收起時不通知，由原生 2 秒後完成（2026-10-09 QA 第 1 輪：舊版對每個 Esc 都通知，動畫開頭的 Esc 被吞；QA 第 2 輪：
舊版失敗只寫 console 卻照樣收起，且在結果出來前就通知原生）。焦點在行內區塊裡的**按鈕**上（例如題組的「還原 AI 版本」、
「取消」、「確認退回」）按 Esc＝稍後再問，不是沒反應。
**And** 原生層完成的 dismissal（Esc 2 秒後備、畫布卡住期間按的 Esc）和網頁「稍後再問」的範圍相同：所有非 internal 的
強制題，加上網頁最後回報的目前題目（面板每次換題都以 `overlay_current` 回報；那一題還沒結案、不是 internal 才算），
每一題各記一次 dismissal、開始新週期；之後的強制題對帳不會因為剩下的強制題又把蓋板叫回來，目前題目不是強制題時也照樣
記 dismissal（2026-10-09 證據畫布第 5 輪 QA：舊版原生後備只處理最早逾時的一題）
**And** 每一題在同一個蓋板 session 裡只記一次 dismissal（2026-10-09 QA 第 3 輪：舊版部分失敗後重試會重算範圍，已成功的
目前題目再記一次，`cycle_number`、`snooze_count` 各 +2）：
- 網頁記住這次「稍後再問」已成功的題，重試只做還沒成功的；server 回「已結案」（題目已在終態）視同成功（那一題已經不用
  再問）。已成功的題之後在同一個 session 裡又到期變成強制時，下一次稍後再問照樣記它（那是新的一次強制）。
- 網頁的 dismissal 走原生層（`dismiss_question`），原生層記下這個 session 裡蓋板網頁已記過的題（以記完後的週期編號為準）；
  原生後備（Esc 2 秒、畫布卡住）逐題 dismissal 前先看這本帳，網頁已處理（或正在處理，兩條路排隊、不並行）的題跳過。網頁的
  dismissal 超過 2 秒才成功、或部分失敗交給原生後備時，同一題都不會被記兩次；網頁比原生慢、晚到的那一次也一樣跳過

### 場景 7：卡住的蓋板 session 可以自我修復

**Given** 蓋板 session 已開啟
**When** (a) 再次收到顯示請求但內容尚未確認；(b) session 內所有題目都已由其他通道結案；(c) 使用者在面板裡答完
最後一題；(d) session 開著時另一題到期變成強制；(e) 蓋板收起（稍後再問、完成、Esc、讓開）
**Then** (a) 重送待播轉場而不是早退；(b) 被其他通道結案的題在 session 裡就地標成已結案、不能作答（decision-surface
場景 16）；全部都結案、而面板**當下**沒有在顯示這次 session 裡在面板送出的回執時，蓋板隱藏並結束 session，不留下
無題可答的全螢幕視窗——「保留回執」只在面板正顯示那張回執時成立，使用者已經切去看別題就不算；(c) 蓋板保留回執（交付
狀態、AI 回饋輪詢），直到使用者按「完成 ⏎」或 Esc 才隱藏並結束 session（decision-surface AC-DS-09；2026-10-09 取代
舊版「全部結案就自動隱藏」，舊版會讓最後一題的回執一閃即逝）；(d) 新的強制題接到 session 尾端（PRD §5.8），「第 N 題，
共 M 題」跟著變多，答完目前的題可以直接前往它；按「稍後再問」時它也一起記 dismissal；(c) 的收起判斷不能早於這次作答的
結果：server 先通知清單變更再回傳作答結果，所以從按下送出到結果回來（作答進行中）蓋板一律不收起；「全部結案、沒有回執
要保留」的收起有 300 ms 緩衝，緩衝期間面板照樣掛著（不卸載），面板一回報正在顯示這次送出的回執就取消收起（2026-10-09
QA 第 3 輪：舊版看到「0 題」就立刻卸載面板，面板來不及回報回執，回執一閃即逝）；(e) 蓋板隱藏後原生層再跑一次
強制題對帳：仍有非 internal 的強制題且 guards 全綠時立刻再呈現（新轉場），沒有就維持隱藏（2026-10-09 QA 第 2 輪：
舊版 session 開著時再要求顯示會被忽略、收起只隱藏不重新檢查，蓋板開著時才到期的題永遠不會跳出來）

### 場景 8：啟動時已有逾時題（回歸）

**Given** app 結束時有一題已逾 `force_at`，guards 全綠
**When** app 經 launchd 或手動重新啟動
**Then** 3 秒內出現覆蓋正確螢幕、內容完整的蓋板；Esc 有效；不會先出現空白模糊畫面

### 場景 9：自動關閉不誤殺強制題

**Given** 蓋板網頁剛載入，題目清單仍在讀取
**When** 讀取尚未完成
**Then** 不因「暫時沒有題目」而自動關閉；只有 server 回報該 session 的佇列確實為空才關閉

### 場景 10：勿擾狀態讀取失敗不讓收件匣失效

**Given** 勿擾狀態讀取失敗（例如 SQLite 暫時錯誤）
**When** shell 對帳主動 surface
**Then** 沿用最後一次成功讀到的勿擾狀態；若啟動後從未讀成功，持續重試，60 秒後仍失敗則視為未啟用、
寫診斷並發 Discord 告警；不得因讀取失敗把所有 surface 永久隱藏

### 場景 11：來源 AI 圖示可辨識

**Given** 題目來源為 Claude 或 Codex，且未指定 `visual_symbol`
**When** 決策面板頁首、邊緣瀏海、主 app 的 Agents／Onboarding 或任何粒子效果顯示來源圖示
**Then** Claude 使用官方星芒向量輪廓（取自 Claude App 內建 AppLogo）、Codex 使用花瓣雲加 `>_` 輪廓；任何粒子
效果的目標點取樣自同一向量路徑，不再使用 `✳`、`⌬` 等文字符號；`visual_symbol` 只能覆寫粒子輪廓

## 測試對應

- Rust 純函數：`overlay_target_frame(displays, anchor)` 以本機三螢幕 fixture（內建 1728×1117@2x、上方與
  左方 1x 外接）驗證；以「`setContentSize` 固定左下角」的模擬視窗模型重現舊順序的 317 pt 偏移（紅），
  並驗證新流程在任何初始大小下都正確（綠）。
- Rust 狀態機：蓋板呈現 handshake（休眠 → 等網頁 → 等掛載 → 開啟）表驅動測試，clock 可注入，枚舉
  逾時、重送、renderer reload、勿擾優先隱藏、session 全結案。
- UI（vitest）：模擬「監聽註冊前送出的事件會遺失」的事件匯流排，驗證掛載時主動拉取與 ack；mock 預設
  不再塞入 transition；Esc 在題目卡未掛載時仍觸發關閉；`overlayShellAction` 在面板保留回執時不自動關閉；
  Esc 是否通知原生的判斷表（掛載、收起中、行內輸入框、行內區塊的按鈕、輸入法組字）；`mergeQuestionSession` 接上新強制題、
  更新被其他通道結案的題；`holdingReceipt` 只在面板正顯示這次送出的回執時成立；稍後再問失敗不收起、成功後才通知原生；
  瀏海圖示中心回報（`ui/src/notchAnchor.ts`）。QA 第 3 輪：`overlayShellAction` 的 `answering`（作答進行中不收起）與
  `overlayShellMounted`（收起緩衝期間面板照樣掛著）、依事件順序模擬「清單先變空、作答結果後到」的收起計時（
  `ui/src/surface/surfaceRound3.test.tsx`）；`runLater` 的 `done`（重試只做還沒成功的、「已結案」視同成功）與 `forgetDueAgain`
  （在同一個 session 又到期的題照樣記）。
- Rust：`overlay_presenter::dismiss_targets`（原生 dismissal 的範圍：全部非 internal 強制題＋最後回報的目前題目，
  不重複、不含終態與 internal；`native_dismissal_matches_the_web_later_scope`）；`overlay_presenter::DismissLedger`（同一個
  session 每題只記一次：`native_fallback_skips_questions_the_web_already_dismissed`、
  `web_dismissal_slower_than_the_escape_fallback_is_not_repeated`、`a_question_due_again_in_the_same_session_is_dismissed_again`、
  `a_new_session_forgets_earlier_dismissals`）；`overlay_geometry::overlay_origin`（有點擊用點擊、沒有用瀏海最後回報的圖示中心、都沒有才用估計值）；
  `overlay_plan`（`src-tauri/src/lib.rs`：蓋板收起後 session 已結束，仍有強制題且 guards 全綠就再呈現；session 開著時
  沒有強制題也不收）。
- 手動：真實多螢幕（外接在上方、混合倍率）、launchd 開機啟動、睡眠喚醒、他 app 全螢幕時的蓋板位置與
  焦點。實際 frame 的佐證看殼層 tracing log（launchd 版寫到 `/tmp/me.ray.kunsu.err.log`）：每次顯示記一行
  `蓋板已顯示：目標 Some(Rect…)，實際 Some(Rect…)`，對不齊時另記 `蓋板 frame 未對齊`，螢幕改變記 `螢幕配置改變，蓋板改對齊`。
  沒有另做 `overlay_diagnostics` 指令（2026-10-09 QA 第 2 輪：舊文寫的指令從未存在，改寫成實際的診斷方式；這幾行 log
  已足夠比對目標與實際 frame，另做指令只是多一個要維護的介面）。
