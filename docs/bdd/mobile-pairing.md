# 手機配對與作答通道（PRD §30.8；docs/design/mobile-relay.md）

> 狀態：**Target**（2026-10-12）。

## 背景

手機經使用者的 Zeabur 中轉站連到 Mac 上的 Kunsu。答案只能來自使用者本人的通道（含已配對手機）；AI agent 的 MCP 永遠不能作答。

## 場景

1. **掃描配對**：Given 主視窗按「配對新手機」，When 手機掃 QR，Then 主視窗跳出「<裝置> 要配對」；按允許後手機顯示待處理題目。
2. **沒按允許就不成立**：When 主視窗按拒絕或 5 分鐘內沒按，Then 手機顯示配對失敗，裝置清單不變。
3. **配對碼一次性**：When 同一個 QR 被第二支手機掃，Then 拒絕。
4. **手機作答**：Given 已配對，When 手機回答一般題，Then Kunsu 記下答案（channel=mobile），電腦上的題目同時消失。
5. **手機批准動錢**：When 手機在核對畫面按「批准並執行」，Then 走簽章鏈；沒有經過核對的動錢答案被拒絕。
6. **偽造與重放**：簽章錯、已撤銷裝置、重送舊封包、時間差 > 120 秒的請求一律拒絕，不寫答案。
7. **中轉站看不到內容**：中轉站收到的封包內容是密文；中轉站不寫硬碟。
8. **撤銷**：主視窗撤銷裝置後，該手機的請求全部被拒，手機顯示「已被撤銷，請重新配對」。
9. **AI 不能作答**：MCP 工具清單裡沒有任何作答或批准工具（既有測試保留）。

## 驗收條件

- [ ] AC-MP-01 配對碼 5 分鐘過期、只能用一次（Rust 單元）
- [ ] AC-MP-02 配對需要主視窗按允許才寫入裝置清單（Rust 單元＋UI）
- [ ] AC-MP-03 手機封包驗證：簽章、裝置清單、撤銷、seq、時間窗（Rust 單元，table-driven）
- [ ] AC-MP-04 加解密互通：Swift 封裝、Rust 解開（與反向）用同一組測試向量（Rust＋Swift 單元）
- [ ] AC-MP-05 手機作答以 channel=mobile 寫入；動錢必須 money_confirmed（Rust 整合）
- [ ] AC-MP-06 中轉站只轉送、不解析內容、不落地；Mac 需 token、裝置只能找指定 Mac（中轉站單元）
- [ ] AC-MP-07 MCP 面沒有作答寫入（`inv_no_answer_via_mcp` 保留）
- [ ] AC-MP-08 主視窗「手機」卡片：配對 QR、待允許、裝置清單、撤銷（UI 測試＋瀏覽器）
- [ ] AC-MP-09 手機首次打開是掃描畫面；配對成功後進入一問一答（模擬器）
