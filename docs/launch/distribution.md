# Kunsu 推廣策略（Distribution）

> PRD §31.8。2026-10-13 初版，草案。

## 1. 先講清楚目標

目標是讓 Kunsu 成為廣為人知的 App。Kunsu 是開發者工具：只有同時讓好幾個 AI Agent 在跑的人才有這個痛。
所以先打穿這群人，再往外擴：

| 階段 | 目標 | 判斷能不能往下走 |
|---|---|---|
| 0. 內測 | 10～20 位重度 Claude Code／Codex 使用者裝起來、連用兩週 | 一半以上兩週後還在用；每人每週至少回 10 題 |
| 1. 開源發表 | 1,000 GitHub 星、500 組 Mac＋手機配對 | 週活躍配對數成長，不是只有星星 |
| 2. 開發者圈擴散 | 1 萬活躍使用者 | 自然新增（非發表週）佔一半以上 |
| 3. 往外 | 讓「AI 會叫你起來做決定」變成一般知識工作者也懂的概念 | 非工程師使用者比例 |

## 2. 目標使用者與一句話

- **誰**：每天開 3 個以上 Claude Code／Codex 對話、讓 AI 跑長任務的獨立開發者與小團隊工程師。
- **痛**：AI 卡在等你回答，你沒看到，整條工作停一整晚。
- **一句話**：「AI 卡住要你決定時，Kunsu 會把問題帶到你面前——躺在床上用手機也能回。」
- **差異**：內容不離開你的 Mac、開源可查；不是又一個通知 App，是會逼你回應的收件匣。

## 3. 通路（依優先順序）

1. **Claude Code 外掛目錄與 Codex 外掛**：Kunsu 本來就是外掛，裝外掛就是下載入口。這是最便宜、最精準的通路。
2. **GitHub 開源**：README 開頭放 20 秒影片（AI 卡住 → 手機跳題 → 床上點一下 → AI 繼續）；一行安裝。
3. **發表日**：Hacker News 的 Show HN、Product Hunt、X、Threads 同一週。HN 標題直接講痛點，不講功能。
4. **作者自己的社群帳號與部落格**：建造過程公開——「讓 AI 當最嚴厲的父親」系列，每篇附一個真實截圖。
5. **示範影片**：15～30 秒直式短片，一支一個場景（半夜 AI 卡住、會議中不打擾、動錢先核對）。
6. **開發者社群**：Claude Code、Codex 相關 Discord／Reddit／台灣開發者社群，以分享用法為主，不洗版。

## 4. 內建擴散

- 外掛文件裡有「Kunsu 讓 AI 在需要你時把問題送到你面前」的說明，別的開發者看到 AI 的行為就會問。
- 手機回答後的回執可以分享成圖片（不含內容，只有「3 分鐘內讓 4 個 AI 繼續工作」這類數字）。
- 開源 repo 的 issue 與 discussion 作為社群據點。

## 5. 衡量

- 漏斗：官網造訪 → 註冊 → 下載 Mac 版 → 首次設定完成 → 配對手機 → 第一題被回答 → 第 7 天仍有回答。
- 北極星：每週「被 Kunsu 救回來的 AI 工作」數（回答後原對話接續成功的次數）。
- 只收帳號與匿名使用次數；不收任何題目內容（§31.2）。

## 6. 時程（草案）

- 第 1～2 週：去個人化、帳號、多租戶中轉站、官網。
- 第 3 週：Mac 公證版＋TestFlight 內測。
- 第 5 週：內測達標後開源發表＋App Store 上架。
