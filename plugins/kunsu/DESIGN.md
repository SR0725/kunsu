# Kunsu 外掛設計

目的：當 Claude 或 Codex 缺少使用者的正式判斷，可靠地把問題交給 Kunsu，並將答案帶回原對話完成工作。
已授權的日記／復盤是督導承諾。嚴厲表現在問題清楚、要求回應、追蹤結果；語氣直接，不羞辱、不偽造急迫性。

## 身分與呈現

- 名稱：Kunsu 軍師；短描述：需要你的決定時，讓 AI 正式來問你。
- App、listing、composer 使用選定的原始 K；不重畫、不添加另一套符號。
- 原生 Kunsu 負責選項、正式送出與金錢參數。外掛提供工具、技能與草稿，不另建聊天介面。
- 首行說明要使用者決定／回應什麼，再列已知事實、建議與各選項後果。未知有標記；範本內容不能當真實證據。

## 工作流程

```mermaid
flowchart LR
  A[查清事實與可逆準備] --> B[準備草稿]
  B --> C[dry-run 並看預覽]
  C --> D[正式送到 Kunsu]
  D --> E[使用者原生介面作答]
  E --> F[原對話接續]
  F --> G[結果回報]
```

Codex 發問後交還控制權；Claude 用既有背景 waiter。每次都保留真實來源 id/cwd；不可把外掛共用行程的身分猜成發問者。
關閉、沉默、超時都不是同意；讀到答案不是完成，最後必須回報實際結果。緊急與 T0 分開，分級沿用 app 契約。

## 維護與復原

`manage.py install` 先驗證 package、設定與唯讀連線，再備份並用宿主 plugin add 安裝。只改 Kunsu 的三個設定表與一個 marketplace entry；其他內容保留。
共用 Claude 技能以逐檔更新保留個人附加檔案。失敗保留備份與嘗試版本；外部並行修改不強行覆蓋。
`doctor` 的成功必須有握手、14 tools 與 dnd_get 實際證據。它不建題、不修改勿擾、不自動修設定。
`draft` 只建立本機資料夾；已存在的草稿與非法 id 拒絕，避免把新範本覆蓋正式決策證據。

## 驗收邊界

本機打包、安裝、宿主唯讀工具與草稿 dry-run 各有獨立證據。真人作答與原對話接續不能用 Agent 代答來補驗收。
沒有排程時間就不新增排程；沒有私有帳號／公開發布需求就只安裝本機版本。
