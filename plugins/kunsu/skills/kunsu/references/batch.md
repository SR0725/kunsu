# 題組（`kind: batch`）— 一批同類工作一次問完

一題放 1–20 個同類項目，使用者在同一個面板看完、改完、決定完，你再照確認過的內容逐項執行。

## 什麼時候用

- ✅ 一批同類、彼此獨立、可一次按「全部送出」、不需逐項確認的工作：回信草稿、Threads／IG 留言回覆、客服回覆、廣告文案變體、
  退款或報帳逐項核可、要不要隱藏某些留言。
- ✅ 單項回覆／重擬也用 batch，保留可編輯輸入框。超過 20 項 → 先自己篩，或拆成兩題（例如「學員問題」「合作邀約」）。
- ❌ 項目彼此有取捨（只能挑一個）→ 用 `choice`。
- ❌ 任何一項會動錢（改預算、出價、付款）→ 不能放題組，錢題一題一題走 SKILL §5。
  退款核可只是「使用者同意後由你在金流後台操作」時可以放題組；Kunsu 不代為動錢。

## 每一項怎麼寫

| 欄位 | 寫什麼 |
|---|---|
| `id`（項目） | 題內唯一、穩定（`i1`、`mail-<信件 id>`）。只能用英數、`.`、`_`、`-` |
| `title` | 一眼認出是哪一項：寄件人＋主旨、留言者帳號、申請人（≤80 字） |
| `subtitle` | 選填：主旨、方案與金額。≤200 字 |
| `context_md` | 原文：來信全文、留言串（含上下文）、申請內容。Markdown；左欄會跟著選中的項目顯示 |
| `proposal` | 你的草稿（回信、回覆）或建議（「符合退費規則 → 建議全額退款 NT$4,800」）。≤5,000 字（只核可的建議也一樣） |
| `editable` | 可以直接改草稿的寫 `true`；不能改文字、只能照建議／不處理／請你改的寫 `false`（退款、分類、隱藏留言） |
| `default` | 預設 `approve`；你認為不該回的（促銷信、情緒性留言）寫 `skip` 並在 `default_reason` 寫原因 |

草稿用使用者的語氣寫（有語氣指南就先讀），要能直接送出：稱呼、簽名、連結都寫好，不要留 `[TODO]`。

**不准佔位文字（鐵律）**：`default: skip` 的可編輯項目，`proposal` 要嘛是空字串 `""`，要嘛是一封真的可以送出的回覆。
**絕對不要寫「（不回）」「（建議不回）」這類佔位文字**——不回的原因寫在 `default_reason`。使用者改主意按「採用」時，
草稿框裡的文字就是會一字不改送出的文字；空草稿他得先寫好內容才能採用（面板與 server 都會擋空的採用）。

**題組 id 長度**：題組 id 最多 116 字（不含 `-r2` 這類輪次後綴）。題目 id 上限 120 字，要留空間給第 2 輪以後的
`<原 id>-r2`～`-r99`；超過會被 400 `batch_id_too_long` 拒收。題組不能帶 `kongko_ref`（400 `batch_kongko_ref`）。

## 拿到答案之後（鐵律）

`ask_get` 的 `answer.items` 是逐項決定 `{item_id, action, text?, note?}`，`answer.free_text` 是使用者的整體指示（可能沒有）。

1. **採用（`approve`）**：可編輯項目的 `text` 就是要送出的最終文字，**一字不改送出**——不潤稿、不加稱呼或簽名、
   不修標點、不換行。使用者確認的就是對方會看到的（所見即所送）。只核可的項目照你原本的建議執行。
2. **不處理（`skip`）**：不要動，封存即可。
3. **請 AI 改（`revise`）**：先執行所有採用的項目，再依每項的 `note`（與整體指示）重寫，然後建**第 2 輪題組**：
   - id：`<原 id>-r2`（第 2 輪的題再被退回就是 `-r3`，依此類推）。
   - 只放要重看的項目，沿用原本的 `item_id`；`why` 第一行寫「第 2 輪：<原題 id> 退回的 N 項，已依你的指示重寫」。
   - 建完照 SKILL §4 結束輪次，讓正式答案接回。
4. 全部做完 `ask_report`：`summary_md` 寫「已送出 N 項、不處理 K 項、重寫 L 項（第 2 輪題組 `<id>-r2`）」，
   有送不出去的逐項寫原因（status 用 `failed` 或 `blocked`）。

收到 `[Kunsu] 使用者已回答你在這段對話提出的題組…` 的訊息時，訊息裡已列出每項的決定與最終文字，照上面四步做。
